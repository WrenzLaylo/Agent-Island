# v0.4.1 — Concurrent sessions

Agent Island modelled agents, not sessions. `IslandSnapshot.agents` is a
`Record<AgentId, AgentSnapshot>` — three fixed slots — so N live sessions were
flattened into one snapshot per agent and surfaced as an unactionable string:

```ts
live.length > 1 ? `${live.length} sessions open` : ...
```

"3 sessions open" named no session and reached none. Everything downstream
inherited that mismatch. This release addresses the multi-session case for all
three agents.

## Approval buttons re-arm before accepting a click

**The one safety fix here.** Answering an approval promotes the next queued one
straight into the same card, with its buttons in the same screen position the
cursor is already resting in. The only gate was `isMorphing`, driven by a
resize effect keyed on `[size.width, size.height]` — and consecutive cards with
the same number of choices resize to the *same* height, so that effect never
re-ran and never disarmed anything. The second half of an accidental
double-click answered a request the user had not read.

`APPROVAL_REARM_MS` (350ms) now holds every button inert whenever the displayed
request id changes. It covers deny as much as approve: answering "No" to a
request you never read still interrupts an agent that was waiting on you.
`approvalReArmed()` also guards the click handler itself, so keyboard
activation and replayed events are refused, not merely un-clickable.

## One row per session, replacing the agent tabs

Past one session, "which agent" stops identifying anything actionable — two
Claude sessions are one tab. With 2+ sessions the expanded panel lists sessions
instead: agent mark, folder, terminal, busy/idle dot, pending-approval count.
With 0 or 1 session the agent tabs are unchanged, so the common case looks
exactly as it did.

Ordering is by start time, oldest first, and deliberately does **not** float
busy or approval-pending sessions to the top. Rows that reorder underneath a
cursor are the same hazard as the re-arm window: the user aims at one row and
the list moves a different one under the click.

Beyond four rows the list scrolls rather than growing the window — an island
tall enough for ten sessions stops being an island.

## Disambiguation only where it is earned

Rows show agent, folder and terminal. A `pid` qualifier is appended only when
all three collide and the row would otherwise be a literal duplicate. Sessions
separated by folder, by terminal, or by agent get no extra noise.

`folderName()` moved from `IslandShell.tsx` into `src/shared/session-list.ts`
and is now unit-tested across Windows paths, POSIX paths, trailing separators
and bare drive roots — the shape that previously regressed when a `[\/]`
character class collapsed to forward-slash only and printed whole paths.

## Handoff goes to the session you picked

`handoffToTerminal` already accepted a `sessionId`; the renderer omitted it, so
the manual path fell through to `newestSessionFor(agentId)` — fine with one
session, a coin flip with three. Clicking a row now raises that exact terminal.
Sessions whose host exposes no raisable window (VS Code panels) render disabled
with an explanatory tooltip instead of failing silently on click.

## Status line describes the whole list

The per-agent `activityLabel` counts only the *active* agent, which read as a
contradiction directly above a list spanning every agent — "3 sessions open"
sitting on top of four rows, because the fourth belonged to Codex. When the
session list is showing, the headline and summary are computed across all
sessions: `5 sessions · 1 working`.

## Verification

100 unit tests (was 77). Both tsconfigs clean, build clean.

Live-verified against an isolated registry (`LOCALAPPDATA` redirected to a
scratch root) so the developer's real sessions were never touched:

- five concurrent sessions across Claude and Codex — ordering, per-row folders,
  `pid` fallback on the two fully-colliding rows, no qualifier elsewhere, and
  the scroll cap
- the global summary line reading `5 sessions · 1 working`
- an approval card's buttons dimmed and inert on mount, then live once the
  re-arm window elapsed (temporarily widened to 4000ms to observe it
  deterministically rather than racing a 350ms timer)
- 0 sessions falling back to the agent tabs

Not verified: multi-monitor handoff, and Codex/Hermes adapters against real
installs of those agents.
