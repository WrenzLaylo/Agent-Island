# v0.4.0 — real terminal integration

Agent Island no longer launches agents, owns pseudo-terminals, or renders a
terminal of its own. It observes agent sessions running in the user's real
terminal windows, and "Continue in Terminal" raises the actual window hosting
the actual session.

## What was wrong

Worse than "handoff opens the wrong window". The only caller of `pty:start` was
`TerminalWindow.tsx`, the xterm viewer — so the chain was:

> click "Continue in Terminal" → `handoffToTerminal` → `createTerminalWindow` →
> loads `terminal.html` → React mounts → `ptyStart` → **spawns a new agent**

"Continue in Terminal" did not surface your session. It started a second one.
A ConPTY has no window, so there was never an original terminal to return to,
and an agent started by the user was invisible to the island entirely.

## How a session is now identified

There is no API for "which window am I in":

| Host | Shell owns a window? | Measured |
|---|---|---|
| conhost (`cmd`, `powershell`) | yes — `ConsoleWindowClass`, owned by the shell's own pid | pid → HWND works |
| Windows Terminal 1.24 | no — a 0×0 `PseudoConsoleWindow` | shell is a direct child of `WindowsTerminal.exe`, but that one process owned **4 visible windows** at once |
| mintty (Git Bash) | no — window owned by `mintty.exe` | mintty is the shell's ancestor |
| VS Code | no window at all | terminal is a panel, not a window |

So the wrapper performs a **title handshake**: set a unique window title, find
the window now carrying it, restore the title, cache the HWND. Both mechanisms
are used because neither covers everything —
`SetConsoleTitleW` (via `process.title`) for Win32 consoles and Windows
Terminal, and `OSC 0` for mintty, VS Code and other xterm-compatible emulators.

Three constraints this has to respect, all found by measurement:

- Shells overwrite the title continuously, so the handshake is momentary and
  happens once at startup.
- A terminal's window title tracks its **active tab**, so resolution must happen
  while the session's tab is active — true at session start, which is when the
  wrapper runs.
- It must happen **before** agent discovery: discovery shells out to
  `<agent> --version`, and those children share the console and can clobber the
  title mid-handshake.

`WT_SESSION` is deliberately not trusted: it is inherited by child processes, so
a mintty session launched from a Windows Terminal tab reports a stale one. The
resolved **window class** is the source of truth for terminal kind.

## Architecture

```
island <agent>                     Agent Island
  ├─ resolve host window            ├─ SessionWatcher
  ├─ write sessions/<id>.json  ───► │   reads sessions + prompts
  ├─ run the agent in a pty         │   validates pid + HWND liveness
  ├─ scan output for prompts        │
  ├─ write prompts/<id>.json   ───► │   shows approval / "needs input"
  └─ read decisions/<id>.json  ◄─── └─ writes decisions/<id>.json
```

Files, not sockets: it is the mechanism the Hermes bridge already proved on this
machine, it survives either side restarting, and it needs no port or handshake.

The wrapper owns a pty **inside the user's real terminal**, so every existing
detector (`hermes-approval`, `codex-approval`, `terminal-input`) keeps working
unchanged against a genuine window. Known approvals stay answerable in the
island; only unsupported prompts trigger handoff.

## Window raising

`raiseWindow` restores if minimised, optionally relocates to the island's
display, then focuses. Maximized windows are dropped to restored before the move
and re-maximized after, so they fill the *target* monitor.

`SetForegroundWindow` is refused for processes that do not own the foreground
window, so the helper attaches its input queue to the current foreground thread
first and then **verifies** the result rather than assuming it, returning
`foreground` / `raised` / `raised-not-foreground` / `gone`. `gone` is surfaced to
the user as "that terminal has been closed" — the island never opens a
replacement, because that would start a new agent.

## Shell integration

`claude` / `codex` / `hermes` shell functions route through the wrapper, written
between markers into the PowerShell profile and `.bashrc`, with a one-time
backup and an exact uninstall. They are **fail-open**: if the wrapper or the
Electron runtime is missing, they fall through to the real executable. A shim
that shadows the user's agent must never be able to cost them that agent.

Installed on completing onboarding; Settings has Install/Remove.

## Removed

`TerminalWindow.tsx`, `terminal.html`, `terminal-main.tsx`, `terminal.css`, both
`@xterm/*` dependencies, `createTerminalWindow`, `centreTerminalOnIslandDisplay`,
the whole `pty:*` IPC surface and its preload API, and the PTY smoke scripts.

`PtyManager` and every detector survive — they moved into the wrapper — so all
56 tests still pass unchanged.

## Also fixed

`src/renderer/env.d.ts` imported `IslandApi` from `../../preload/index`, a path
that does not exist, which silently degraded the entire renderer bridge to
`any`. Corrected to `../preload/index`; that alone surfaced four real call-site
errors.

## Runtime: plain Node, not Electron

The wrapper runs under **`node`**, not `ELECTRON_RUN_AS_NODE`. Electron is a
GUI-subsystem binary and never attaches to the console it was launched from, so
under it the wrapper saw `stdin.isTTY === false`: raw mode could not be set, so
keystrokes stayed line-buffered and never reached the agent, and VT sequences
were printed as literal text instead of being interpreted. The agent rendered
as a wall of `←[K` and accepted no input.

Measured, same probe in each:

| Runtime | Host | stdin TTY | setRawMode | size |
|---|---|---|---|---|
| electron-as-node | Windows Terminal | false | fails | null |
| node 22 | Windows Terminal | true | ok | 120×30 |
| node 22 | conhost | true | ok | 120×50 |

node-pty ships **N-API prebuilds**, which are ABI-stable across Node and
Electron, so no rebuild or second binary is needed. The launcher prefers `node`
from `PATH` and falls back to Electron only if Node is absent — and in that
case the wrapper now says so and execs the agent directly rather than handing
back a frozen screen.

## The `island` command

`island.cmd` and `island` (bash) are written to `<userData>/bin` on every
launch, so the command exists and points at the current install whether or not
shell integration is enabled. Shell integration additionally prepends that
directory to `PATH`.

This closes a circularity in the first cut of this change: the advice shown when
shell integration was off — "run `island claude`" — referred to a command that
existed nowhere, because the shims only defined `claude`, `codex` and `hermes`.
Settings now shows the launcher's real path until integration is on.

## New

`island --whoami` reports whether the current terminal can be raised, without
starting an agent. Setting `AGENT_ISLAND_WHOAMI_OUT` writes a machine-readable
copy of the handshake result.
