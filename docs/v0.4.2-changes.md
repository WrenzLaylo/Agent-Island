# v0.4.2 — Questions, typing, and a stuck panel

## The stuck "needs input" panel, and why settings vanished with it

Closing a terminal left the island insisting that agent still needed input.
One line caused it:

```ts
setTerminalInput((current) => (current && current.id.startsWith(session.id) ? null : current))
```

`current.id` is a prompt id, minted as `claude-<timestamp>-<random>`. It never
carried the session id as a prefix, so that test could not match — the cleanup
on session death was dead code from the day it was written.

Two consequences followed from it, and the second is why settings appeared to
disappear:

- The pill kept announcing "needs input", and clicking it reopened the same
  handoff panel.
- **The handoff panel has no settings button** — the gear only exists in the
  overview. A permanently stuck handoff panel therefore also removed the only
  route to settings. Installing Codex was a coincidence, not a cause.

Three fixes, because one was not enough:

1. Match on `sessionId`. Queued approvals belonging to a dead session are
   invalidated too — they could never have been answered either.
2. A liveness sweep for handoff prompts, mirroring the one approvals already
   had. A prompt is dropped when it expires or when its session leaves the
   registry, so a single missed event can no longer strand the UI.
3. The panel's ✕ now dismisses the prompt rather than merely collapsing. It
   previously left the prompt in state, so the pill immediately re-announced
   it — there was no way out of the panel at all.

## Questions are answerable in the pill

Plan mode was reaching the island as an unanswerable handoff. The detector
requires both poles of a permission prompt — a bare `Yes` and a `No` — and plan
mode offers neither:

```
Do you want to proceed?
1. Yes, and auto-accept edits
2. Yes, and manually approve edits
3. No, keep planning
```

None of the affirmative options are `once`, `session` or `always`. Rather than
stretch that vocabulary to cover them, the detector now carries **every
numbered option verbatim** and marks the panel `isPermission: false`. Forcing
"Yes, and auto-accept edits" into `always` would have told the user they were
granting a standing permission, which is not what Claude offered.

A non-permission panel renders as a `ChoiceCard`: the question, the options
exactly as written with their own digits, and no approve/deny language
anywhere. The header reads "Claude is asking", not "Approval required".

Answers are sent as `optionIndex`, and the wrapper presses that digit — the
agent's own numbering, never a translation.

## Typing in the pill

The same card carries a text field. Typing sends the text followed by Enter,
exactly as if typed in the terminal, so a question with no usable option list
is still answerable without leaving the pill. Control characters are stripped
before the text reaches a live TTY, where an embedded escape would be
interpreted rather than typed.

"Continue in Terminal" is demoted to a link: the island can answer this now, so
switching windows is the fallback, not the headline.

The IPC accepts exactly one of `decision`, `optionIndex` or `text`. More than
one would leave the wrapper to choose, and it would choose by precedence rather
than by what the user meant.

## Verification

109 unit tests (was 100), both tsconfigs clean, build clean. Nine new detection
tests cover plan mode, a question sharing no vocabulary with permissions, the
refusal to relabel auto-accept as permanent, distinct fingerprints, and a plain
numbered list still being ignored.

Live-verified against an isolated registry, reading back what the island
actually wrote to the wrapper's inbox:

- clicking "Yes, and manually approve edits" wrote
  `{ "optionIndex": 2 }` — no `choice` field
- typing a reply and pressing Enter wrote
  `{ "text": "use SQLite instead" }`
- the reported stuck panel reproduced exactly, then cleared on session death

Not verified: a real Claude plan-mode session end to end (the staged prompt
matches the captured shape, and the detector is unit-tested against it, but the
loop from Claude's own TUI through to the keystroke has not been run);
multi-monitor handoff; Codex and Hermes plan-mode equivalents.
